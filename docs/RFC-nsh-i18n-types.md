# RFC: Type-Safe `nsh/i18n` Declarations Generated from `locales/`

- **Target**: `longbridge/nsh` (`crates/nsh-bundler`, `crates/nsh-js`, `crates/nsh-i18n`)
- **Status**: Prototype verified in `nsh-music` (`scripts/i18n.mjs`, `src/i18n/`, `tests/i18n.rs`)

## Motivation

NSH already provides strong compile-time type safety for design tokens by generating `.nsh/types/nsh/tokens.d.ts` from `theme.json` via module augmentation:

```ts
// .nsh/types/nsh/tokens.d.ts
import "nsh";

declare module "nsh" {
  interface Tokens {
    "background": string;
    "primary": string;
  }
}
```

However, `.nsh/types/nsh/i18n.d.ts` currently types `t` loosely:

```ts
export declare function t(
  key: string,
  options?: { locale?: string; [name: string]: unknown },
): string;
```

As a result, typos in keys, missing `%{param}` arguments, or mismatched parameter names pass `nsh check` silently and only surface at runtime as `<locale>.<key>` or unreplaced `%{param}` placeholders.

## Proposal

Follow the exact same pattern as `tokens.d.ts` by generating `.nsh/types/nsh/translations.d.ts` automatically whenever `locales/` exists beside `nsh.json`.

### 1. Augmentation Interface in `nsh/i18n`

In `crates/nsh-js/src/i18n.rs` (which emits `.nsh/types/nsh/i18n.d.ts`):

```ts
/** Augmented by `.nsh/types/nsh/translations.d.ts` from `locales/`. */
export interface Translations {}

/** Known locale tags augmented from `locales/`, falling back to `string`. */
export interface TranslationLocales {}

export type TranslationKey = keyof Translations extends never ? string : keyof Translations;

export type LocaleTag = keyof TranslationLocales extends never
  ? string
  : keyof TranslationLocales | (string & {});

export declare function t<K extends TranslationKey>(
  key: K,
  ...args: K extends keyof Translations
    ? keyof Translations[K] extends never
      ? [options?: { locale?: LocaleTag }]
      : [options: Translations[K] & { locale?: LocaleTag }]
    : [options?: { locale?: string; [name: string]: unknown }]
): string;
```

Notice the graceful fallback:
- When an app has **no `locales/`** (so `Translations` stays `{}`), `keyof Translations extends never` evaluates to `string`, preserving 100% backward compatibility.
- When an app **has `locales/`**, `nsh-bundler` emits `.nsh/types/nsh/translations.d.ts` and lists it in `.nsh/tsconfig.json`'s `"files"` array, turning `t(...)` into a strictly checked lookup for both keys and `%{param}` arguments.
- Apps that load runtime translation packs via `addTranslations` can call `t(dynamicKey as string)` or use a `tDynamic` helper.

### 2. Generator in `crates/nsh-bundler/src/types.rs`

`nsh-i18n::read_translations(app_dir)` already parses all rust-i18n files (`_version: 1` and `_version: 2`, YAML/JSON/TOML) at build and `nsh check` time.

Using the base locale (`"en"`, or the first sorted locale if `"en"` is absent), extract all `%{ident}` placeholders from each message and emit:

```ts
// Generated by nsh from `locales/`: the app's translation keys and parameters.
import "nsh/i18n";

declare module "nsh/i18n" {
  interface TranslationLocales {
    "en": true;
    "zh": true;
  }

  interface Translations {
    "account.userMenu": { name: string | number };
    "nav.home": Record<never, never>;
  }
}
```

### 3. Build-time Consistency Checks (Optional Warnings)

Because `nsh-bundler` already inspects `Translations` to compute `bundle_json`, it can optionally emit non-breaking warnings during `nsh build` when:
- a non-base locale is missing keys present in the base locale, or
- a translation's `%{...}` placeholder set differs from the base locale's.

## Prototype Notes (`nsh-music`)

The `nsh-music` repository proves this design against 214 real keys (including template literal calls such as ``t(`player.quality.${id}`)`` and ``t(`player.light.effects.${effect}`)``) with zero casts and zero runtime overhead.
